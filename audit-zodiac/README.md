# 历史生肖边界诊断包（仅供研究，不改变线上预测）

此包在现有 shuangfu 项目基础上添加 **只读研究工具**，不修改 `s45.js`、`s46.js`、`server/model.cjs`、`server/archive.cjs`、GitHub Actions 或页面内容。

## 为什么要加

原规则在 2026年第001–047期的历史计算中沿用2026年2月17日后的生肖表，而 `data/draw-archive-2026.json` 这些期次另有各期 `specialZodiac`。如001期29应为仓库存档的“牛”，固定表对应“虎”。

## 运行

在仓库根目录：

```bash
node audit-zodiac/compare.cjs > audit-zodiac-result.json
node --test tests/*.test.cjs
```

`compare.cjs` 从仓库已存档的开奖数据和当前 `s45.js` / `s46.js` 中读取原有公式，独立显示原固定映射与历史逐期生肖的研究差异，并检查原始预测的号码是否会受到此次修正影响。结果输出到标准输出，不会写入仓库任何存档。

**重要：**这不是线上修复，也不是新预测算法版本。旧服务器提前存档绝不可更改，原研究成绩也应保留原口径。此处只保证上述已审计的三项历史生肖规则复算。S3整体预测引擎、S4.5四肖以及其他跨年度规则不在此包的修复范围。

## 安全部署顺序

1. 在 GitHub 上创建 `audit/zodiac-boundary-2026` 分支，勿直接更新 `main`。
2. 将本包里的 `audit-zodiac/compare.cjs`、`audit-zodiac/README.md`、`tests/zodiac-boundary-audit.test.cjs` 添加到分支。
3. 本地或 GitHub Actions 中运行上述两条命令，确认一致。
4. 再审查生产 `s45.js`、`s46.js`、以及 `server/model.cjs` 是否要升级新的明确版本号；不能直接套入历史替换后无声覆盖旧规则。
5. 若要投产，先做旧版/新版平行运行，验证每期无未来数据泄漏且首次记录留档，再在新的独立观察窗口评估。

更改仅用于历史计算正确性；无论前述回测是否高于随机基准，都不能说明未来开奖的中奖概率会提高。
